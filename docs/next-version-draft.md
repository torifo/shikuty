## バグ修正

### B-1: 同一市区町村が複数ピースに分裂する問題

**現象**
同じ市区町村コード（`municipality_code`）を持つフィーチャーが、TopoJSON内で複数の別フィーチャーとして存在しているため、1市区町村が2つ以上のピースに分かれてゲームに登場してしまう。

**原因**
データパイプラインの dissolve 処理で `municipality_code` 単位の集約が不完全なケースがある（飛び地・行政区の構成など）。

**修正方針**

- **データパイプライン側（推奨）**: `dissolve` の GROUP BY キーを `municipality_code` に統一し、同一コードのポリゴンをすべて `ST_Union` で結合してから TopoJSON を出力する。
  - 対象: `data-pipeline/` の shapefile → PostGIS ロード → dissolve ステップ
  - `municipality_name` が NULL の政令市区は `district_name`（N03_004）で補完する（既存対応済みだが再確認）

- **フロントエンド側（暫定対応）**: `engine.ts` の TopoJSON → GeoJSON 変換後、`municipality_code` が同一のフィーチャーをクライアント側でマージ（`turf.js` の `union` 等）することでも対応可能。ただしデータ側修正が本筋。

**確認観点**
- 政令指定都市の区（例: 札幌市中央区、横浜市鶴見区 等）が1区=1ピースとして正しく扱われるか
- 飛び地を持つ市区町村が MultiPolygon として1ピースに統合されるか

## 新機能

### F-1: ピースを50音順に並べ、重ならないようにする

**概要**
現在のスキャッタエリアはランダム配置のためピースが重なる。50音順にグリッド状に整列させることで視認性を向上させる。

**実装方針**

1. **ソート**: `engine.ts` の `shuffle()` を、`d.name` の50音順ソートに切り替える（または設定でオン/オフ）。
   ```ts
   // 現在
   const pieces = shuffle(puzzleFeatures).map(...)
   // 変更後
   const sorted = [...puzzleFeatures].sort((a, b) =>
     getName(a).localeCompare(getName(b), "ja")
   );
   const pieces = sorted.map(...)
   ```

2. **グリッドレイアウト**: スキャッタエリア（PC: 右45%、スマホ: 下35%）をグリッドに分割し、各ピースの重心を各セルに配置する。
   - セルサイズはスキャッタエリアと総ピース数から自動計算
   - ピースの実際のポリゴンサイズに依存せず重心を均等に分散させるため、重なりをほぼゼロにできる
   - 各ピースの `ox/oy` はグリッドセル中心 - ポリゴン重心 で算出

3. **スマホ対応**: スキャッタエリアが縦に狭い場合はスクロール可能なリスト表示（横スクロール）も検討。

**UX 考慮事項**
- 50音順で並んでいることで目的のピースを見つけやすくなる
- 同音・難読地名のヒント効果も期待できる

### F-2: ドラッグ中ピース名称に送り仮名（ふりがな）を表示

**概要**
ピースをドラッグ中、画面上部の名称バー（`drag-name-bar`）および PC でのツールチップに、漢字を含む地名の場合は読み仮名（ふりがな）を併記する。

**実装方針**

#### データ側
1. `municipalities` テーブルに `yomigana VARCHAR` 列を追加する。
   - N03 データの `municipality_name` はカタカナ読みデータを持たないため、別途付与が必要
   - 候補: 郵便番号データ（JP Post）・国土数値情報の読み仮名付きデータ・ ICU/Kuromoji での機械変換

2. Rails API の `/api/v1/topojson/:layer` レスポンスに `yomigana` プロパティを含める。

#### フロントエンド側
3. `getName()` に対応して `getYomigana()` を追加。
4. `drag-name-bar` の表示を HTML の `<ruby>` タグを使ったルビ形式に変更。
   ```html
   <!-- 例: 大阪市 -->
   <ruby>大阪市<rt>おおさかし</rt></ruby>
   ```
5. ツールチップも同様に `<ruby>` タグで表示（`tip.html(...)` に変更）。

**UI イメージ**

```
┌─────────────────────────────────────┐
│       大阪市                        │  ← 現在
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│   大阪市（おおさかし）              │  ← 改善後（テキスト形式案）
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│   大阪市                            │
│   おおさかし                        │  ← 改善後（ルビ形式案）
└─────────────────────────────────────┘
```

**送り仮名の範囲**
- 漢字を1文字以上含む場合のみ読み仮名を表示（平仮名・カタカナのみの地名は表示不要）
- 判定: `/[一-龯]/` で漢字の有無をチェック
